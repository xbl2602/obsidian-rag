# 语义搜索控制台（GUI）设计文档

> 日期：2026-08-11 · 状态：已批准 · 技术栈：Python + Flet（Material 3 深色）

## 1. 目标

为 Obsidian 语义搜索引擎（`obsidian-rag`）提供一个**独立桌面窗口**（非浏览器）：
显示索引状态（文件数/块数/耗时/设备）、实时进度、日志，并支持手动触发
增量/全量重建与搜索测试。编程新手友好，中文界面。

## 2. 架构：零侵入的"看门人"模式

```
┌─────────────────────────────┐          ┌──────────────────────┐
│  Flet GUI 进程（轻量）        │  subprocess│ 索引子进程（现有 CLI）  │
│  • 只依赖 flet + 标准库       │ ────────► │  python index.py      │
│  • 不加载模型、不碰 Chroma    │          │  [--full]             │
│  • 显示 + 触发 + 轮询         │          │  • 含锁/显存保护/进度    │
└──────────────┬──────────────┘          └──────────┬───────────┘
               │ 轮询读取（1s 定时器）                │ 实时写入
               ▼                                     ▼
        data/index_progress.json ── 进度/阶段/心跳/统计（现有机制）
        （日志取自子进程 stdout 实时捕获，落盘 data/index.log）
```

**核心决策**：
- GUI 进程**常驻零模型**：不长期占用 GPU 显存，与 MCP server 无冲突。
  仅当用户使用"搜索测试"时才临时加载模型，搜索完释放——这是唯一会
  触碰到重依赖的路径，其余时间只读 progress 文件 + spawn 索引子进程。
- 索引互斥沿用现有 `index.lock` 文件锁（子进程内已有），GUI 只需在
  spawn 前检查锁状态并提示"已有索引任务在运行"。
- 子进程 stdout/stderr 实时捕获 → 内存最近 1000 行 → 同时追加写入日志文件。
- 搜索测试复用 `retriever.py` 的 `hybrid_search`（GUI 进程内调用，加载
  模型仅为临时，搜索后释放；若 MCP server 占用显存，走已有 encode_safe 降级）。

## 3. 视觉设计（Material 3 深色监控台）

### 3.1 风格
深色监控台，Teal 主色。类 Obsidian 深色观感，夜间友好，状态色对比度高。
默认深色，标题栏 IconButton 切换浅色（持久化到 `config.json`）。

### 3.2 色板（hex）
| 角色 | 深色 | 浅色 |
|---|---|---|
| 背景 | `#121212` | `#FAFAFA` |
| 表面/卡片 | `#1E1E1E` | `#FFFFFF` |
| 表面高（输入框/列表项） | `#2B2B2B` | `#F1F3F4` |
| 描边 | `#333333` | `#E0E0E0` |
| 主色 primary | `#4DB6AC` | `#00695C` |
| 主按钮填充 | `#00695C`（白字） | `#B2DFDB` |
| 成功 | `#66BB6A` | `#2E7D32` |
| 警告 | `#FFB74D` | `#EF6C00` |
| 危险 | `#EF5350` | `#C62828` |
| 禁用 | `#616161` | `#BDBDBD` |
| 文字主/次/弱 | `#E0E0E0` / `#9E9E9E` / `#757575` | `#212121` / `#616161` / `#9E9E9E` |
| 日志区底 | `#131313` | `#FAFAFA` |
| 扫描阶段色 | `#64B5F6` 蓝 | 同左深一档 |

### 3.3 字体
界面：`Microsoft YaHei UI`；数字与日志：`Cascadia Mono`/`Consolas`（等宽对齐）。

### 3.4 尺寸规范
卡片圆角 12、按钮/输入框圆角 8、卡片间距 16、卡片内 padding 16、元素间距 12。
深色卡片 1px 描边（不用投影）；浅色用 6% 透明度极淡投影。

## 4. 布局（1280×800，最小 1024×680，启动居中，内容 padding 16）

```
┌──────────────────────────────────────────────────────────┐
│ 语义搜索控制台                              [☀/🌙]       │ ← 56px 头部
├──────────────────────────────────────────────────────────┤
│ 笔记文件  │ 检索块数  │ 最后索引  │ ● 状态卡（点+文案）      │ ← 104px KPI 行 ×4
├──────────────────────────────────────────────────────────┤
│ [增量重建] [⚠全量重建…] [打开Vault文件夹] [打开日志目录]     │ ← 40px 按钮行
├───────────────────────────────┬──────────────────────────┤
│ ① 索引进度 · 心跳灯            │ ② 搜索测试                │ ← 中排（等高）
│   [阶段chip] 已处理 120/1570   │   [输入框……] [搜索]       │
│   ▓▓▓▓░░░░ 43%                │   ┌ 1. 块文本（≤3行）    │
│   预计剩余 21 秒               │   └ 来源.md [块 2/5]     │
├───────────────────────────────┴──────────────────────────┤
│ GPU: RTX 3060 │ 显存 512MB │ 模型 fp16                    │ ← 44px 设备条
├──────────────────────────────────────────────────────────┤
│ 实时日志 [复制] [清空] （仅显示最近 1000 行）               │ ← 剩余高度，min 160
└──────────────────────────────────────────────────────────┘
```

**信息层级**：KPI 大数字（第一眼 3 秒看状态）→ 操作行（状态到动作最短动线）
→ 进度/搜索并置 → 设备条 → 贴地日志（终端习惯位置，需要时才看）。
刻意不做：侧边栏、圆形仪表盘进度。

## 5. 组件规格

- **KPI 卡**：等高 104，flex 均分；上行标签 12px 灰，下行数字 32px/600 等宽；
  第 4 卡为状态卡（12px 色点 + 14px 文案 + 12px 副文案，三态）。
- **按钮**：高 40 圆角 8 间距 8，全部挂 Tooltip；增量=主按钮（Teal 填充），
  全量=红字红描边 OutlinedButton（前缀警告图标 + 省略号"…"暗示有下一步），
  打开类=TextButton 灰字 + 文件夹图标。
- **进度卡**：阶段 chip（扫描蓝/嵌入主色/完成绿，12% 透明度底）；进度条高 8
  圆角 4 随阶段变色；信息行「已处理 X/Y」灰 + 右对齐「N%」20px/600 主色；
  ETA 行 12px 弱灰。
- **搜索卡**：输入框高 44 圆角 8，hint 示例问题，回车/按钮均触发；结果
  ListView 每项：排名徽章（20×20 主色圆白字）+ 块文本 13px 行高 1.5 截 3 行
  + 来源路径 11px 等宽灰 + `[块 k/N]`；最多 5 条，超出提示缩小范围。
- **设备条**：三段式 + 竖分隔线；显存 >80% 数字变警告橙。
- **日志区**：ListView 自动滚动到底；按前缀着色（ERROR 红 / WARNING 橙，
  纯前端着色不改内容）；行 12px 等宽 1.45 行高；头部右侧「复制」「清空」。

## 6. 状态机与空状态

**索引状态三态**（KPI 第 4 卡）：
| 状态 | 色点 | 主文案 | 副文案 |
|---|---|---|---|
| 最新 | 绿 | 索引最新 | 1570 个块均可直接搜索 |
| 待索引 | 黄 | 有变更待索引 | 检测到新/改笔记，建议增量重建 |
| 未索引 | 灰 | 尚未索引 | 点击增量重建开始首次索引（约 40 秒） |

**心跳四态**（10px 圆点 + 文案）：
| 状态 | 表现 | 文案 |
|---|---|---|
| 运行中 | 绿，1s 透明度 0.4↔1 呼吸 | 心跳正常 |
| 卡死 | 红常亮 + 进度条变红 | 疑似卡死，请查看日志 |
| 假活 | 橙常亮 | 进度停滞，疑似卡死 |
| 未启动 | 灰常亮 | 等待任务 |
| 已完成 | 绿常亮（不呼吸） | 索引完成 |

心跳判定逻辑**直接复用现有规则**：心跳停止 >15s → 卡死；心跳正常但进度
>25s 未推进 → 假活。

**空状态**：
- 未索引：进度卡居中 archive 图标 + 引导文案；搜索框禁用（hint「请先完成索引」）。
- 索引中：搜索不禁用，结果区顶部蓝色 info 横幅「索引进行中，结果可能基于旧数据」。
- 无搜索结果：居中「未找到相关内容」+「换个问法，或缩小问题范围」。

## 7. 动效（克制原则）

全部 ≤300ms，仅状态变化时触发：进度条平滑推进（Flet 自带）、心跳呼吸（仅索引
运行时）、KPI 数字 200ms 淡入淡出、状态变化时卡片描边闪主色 300ms、SnackBar
弹出收起、日志自动滚动。禁止：缩放弹跳、粒子、hover 位移、循环动画。

## 8. 交互护栏（新手友好）

- 按钮全部中文动词开头，Tooltip 说明（「增量重建」=只索引新增/修改的笔记，
  约 10 秒；「全量重建…」=删除全部块重新嵌入，约 40 秒）。
- 全量重建 → AlertDialog：「将删除并重新嵌入全部约 1570 个块，预计耗时约
  40 秒。重建期间旧结果仍可查看，但可能不是最新。」按钮 `[取消]`（默认焦点）
  `[确认重建]`（红底白字）。
- 错误：统一 SnackBar（深红底 `#C62828` 白字，4s 自动消失，可手动关闭）
  + 同时写入日志区红色行。不做弹窗堆叠、静默失败。
- spawn 前检查锁：已有索引任务运行则 SnackBar 提示，不重复启动。

## 9. 数据源映射（复用现有文件，零改动）

| GUI 字段 | 来源 |
|---|---|
| 文件数 / 块数 / 耗时 / 设备 | `data/index_progress.json`（stats 字段 + phase） |
| 实时进度 / 心跳 | 同上（files_done/total、heartbeat、phase） |
| 索引状态（三态） | 锁存在 + progress.done + kb_stale 判定（复用 `index.py: kb_stale`） |
| 日志 | 子进程 stdout 捕获 |
| 搜索 | `retriever.hybrid_search`（GUI 进程内） |
| 主题持久化 | `config.json`（新增 `gui.theme` 键，向后兼容） |

## 10. 错误处理与健壮性

- 子进程非零退出 → SnackBar「重建失败，请查看底部日志」+ 日志区红色行。
- progress 文件缺失/损坏 → 显示"尚未索引"灰态，不崩溃。
- 搜索时模型加载失败 → SnackBar「搜索失败：模型加载失败」，输入框可用。
- GUI 进程崩溃不影响索引子进程（子进程独立，跑完自行退出）。
- 窗口关闭时：若索引在跑，仅关窗口不杀子进程（任务继续，下次打开能看到结果）。

## 11. 文件结构

```
obsidian-rag/
├── gui/
│   ├── app.py            # 入口：flet run 或 python app.py
│   ├── theme.py          # 色板/字体/尺寸常量（深浅两套）
│   ├── widgets.py        # KPI 卡、心跳灯、日志区、状态卡等可复用组件
│   ├── worker.py         # 子进程 spawn/监控、stdout 捕获、锁检查
│   └── store.py          # progress 轮询、stats 解析、kb_stale 判定
└── requirements.txt      # + flet（新增一行）
```

依赖仅新增 `flet`。其余全部标准库。

## 12. 测试

- **单元**（tests/）：`store.py` 解析 progress 样例 JSON（含损坏/缺失/各阶段）；
  心跳四态判定；日志行着色规则；锁检查逻辑。
- **手动**：启动 GUI → 观察空状态 → 增量重建（看进度/心跳/日志）→ 搜索测试
  → 全量重建确认框 → 深浅色切换 → 缩窗到最小尺寸。

## 13. 验收标准

1. 窗口打开 3 秒内能回答"索引是否最新"。
2. 增量/全量重建从窗口一键触发，进度条+心跳+日志实时更新。
3. 搜索测试返回带来源路径的结果（与 MCP 检索一致）。
4. 全量重建有确认护栏，默认焦点在取消。
5. 与 MCP server 并发运行时：索引互斥、显存保护不失效（验证无 OOM）。
6. 深浅色切换生效并持久化。
7. 索引子进程崩溃时 GUI 给出明确错误而非静默。

## 14. 明确不做（YAGNI）

- 不做侧边栏/多页导航（单窗口单任务）。
- 不做自动定时重建（手动触发即可）。
- 不做 exe 打包（先 `flet run` 开发运行；打包留 Roadmap）。
- 不做图表曲线（数字 + 进度条已足够）。
