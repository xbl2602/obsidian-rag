# 全库知识图谱重构 · 六套设计方案说明

> 只出方案与静态 mock，不动 `guiweb/` 生产代码。
> 预览：双击 `design-demos/graph-redesign-a-territory.html` / `graph-redesign-b-abyss.html` / `graph-redesign-c-orbit.html` / `graph-redesign-d-tide.html` / `graph-redesign-e-dossier.html` / `graph-redesign-f-bazaar.html` 即可（单文件、内联 CSS/JS、假数据写死、离线零外链）。
> 其中 D/E/F 为内容型追加方案（16 篇带标题＋摘要＋标签的真文字卡，非圆点），直接回应“纯节点不够”的反馈。
> 现状锚点：`guiweb/ui/index.html` 图谱区（搜索岛 g-dock、图层 g-panel、图例 g-legend、缩放 dock、状态行、Inspector gIns、tooltip）· `app.css:720+` · `app.js:1665+`（力导向＋相机＋检索轨道）· `contracts.md` / `FEATURE_PARITY.md`。

用户痛点：**太难看、像杂草；库与库分界不明显。**

三套方案共同遵守的硬约束：

- 系统字体栈 `Segoe UI / Microsoft YaHei / Cascadia Code / Consolas`，无 CDN、无网络字体、无外链图。
- WebView2（Chromium）现代 CSS 可用；**全 demo 零 `backdrop-filter`、零 `will-change`**（问题 53 教训：大面积模糊＋常驻合成层吃显存）。
- 400–600 节点 / 上千边：DOM＋SVG；首屏 1s 可交互策略见各方案「性能」节（共同点：静态首帧 → 同步 settle 封顶 → 按需仿真；标签密度开关；`perf` 档去阴影）。
- 深浅双主题 CSS 变量体系保留；强调色 A/C 沿用冷翡翠系，B 用青碧系（ token 表自洽）。
- 功能零丢失对照（每套 demo 均有落点）：图层（双链 / 语义＋阈值 / 归属 / WEMM 页 / 缓存 / PDF 原件 / 着色三模式 / 边界开关）· 检索（问题节点居中＋三环轨道＋置信度角标＋涟漪）· Inspector（管线 / 双链 / 语义近邻 / 命中片段 / 打开源文件）· tooltip（路径＋块数＋管线）· 图例（形状＋库色 / 生效态）· 力学说明 `i` · 缩放＋百分比＋重置取景 · 库范围过滤 · 底部状态行。

## 方案 A · 领海群岛 Territorial Seas（`graph-redesign-a-territory.html`）

**设计语言一句话：** 同库即同一片领海 —— 用大面积但极淡的库色海域把杂草「泡」成群岛，沿用现有力导向心智，改动最小、观感提升最大。

**布局拓扑：** 力导向聚落（现状演进）。每库一个空间锚点＋语义引力＋边弹簧＋短程斥力保持不变；demo 用固定坐标模拟收敛态，生产仍跑现有 `simStep`，只是锚点引力按领海中心重算。

**库分界手法（本命题重点）：领海式色块。** 每库一块圆角多边形海域：`fill` 8% 库色 ＋ 1.4px 虚线海岸线 ＋ 外圈 7px 淡晕（同色 14%，实线描边实现，无模糊无阴影）＋ 海域顶部库名＋节点数铭牌。关闭「库边界」即退潮（与现状 `lyBounds` 同语义）。

**节点视觉编码（三通道分工）：**

- 形状 ＝ 类型：md／txt／docx 圆角方点 · PDF 折角（`clip-path`）· 缓存菱形 · WEMM 页空心小圆＋虚线药丸（沿用现状形态语言，直接可迁移）。
- 大小 ＝ 重要性：hub（连接 Top5）大一号＋粗字＋`N 块` 计数徽；其余等大。
- 颜色 ＝ 库（默认）／生效态／单色三模式：圆点填充库色；`state` 模式 ok 翡翠 / partial 蓝 / failed 红 / 待处理虚线描边；`mono` 全灰。

**边与标签策略：** 双链实线（跨库桥加粗＋翡翠高亮，标注“桥”语义）· 归属 `2 5` 虚线 · 语义 `1 4` 点线且默认关闭（与现状一致：开语义边才加载嵌入模型，阈值滑杆 0.50–0.85）。标签密度：`k<0.85` 或可见节点多时仅留 hub／命中／选中／悬停标签（现状 `labels-min` 原样保留）。

**检索态 choreography（常态 → 检索 4 拍）：** ① 问题恒星药丸在画布中心落定 ② 三环轨道（90／170／250）淡入＋双重涟漪扩散 ③ 命中沿辐条点亮＋置信度角标（◈ 0.87／0.74／0.61）④ 非命中压暗至 28%、相机平滑推向恒星。清除（✕）即退潮回常态。`prefers-reduced-motion` 下涟漪与过渡全关。

**性能：** 首帧静态领海＋节点（零仿真即可交互）；生产 500＋节点自动进 `perf`（去卡片阴影）；边为 SVG path 常态全量、检索态仅重绘辐条。

## 方案 B · 深渊群岛 Abyssal Archipelago（`graph-redesign-b-abyss.html`）

**设计语言一句话：** 库之间是深渊，岛之内才是陆地 —— 用负空间（海沟）代替一切装饰性边界，节点退化成深渊卵石，默认只看强关系。

**布局拓扑：分簇岛屿（固定岛位＋岛内径向）。** 每库一座固定矩形玄武岩岛台（实底 `#0A0F15` ＋内圈虚线等高线），hub 居岛心、余下环绕，页／缓存做其 PDF 的卫星。岛位永不重叠，从根本上消灭“叠罗汉”。生产实现：锚点改为岛台中心＋强库内引力＋跨库斥力放大（现有 `simStep` 加两行权重即可）。

**库分界手法：群岛深渊（负空间＋海沟中线）。** 岛台之间留 60–120px 真空带＋ `2 8` 点线海沟中线＋ `TRENCH`＋深度标尺（左上 `DEPTH −1200m`）。无任何大面积填充 —— 深浅主题下都是“纸／夜空”本身做分界，最省显存、最耐脏数据（库再多也只是多一座岛）。

**节点视觉编码：**

- 形状 ＝ 类型（卵石化）：md 圆角方 · PDF 实心折角块 · 缓存 45° 旋转菱形 · 页 14px 虚线小环；字形直接打在石上（W／混／综／PDF／◆），远看即识类型。
- 大小 ＝ 重要性：仅 hub 放大＋外圈光环（`box-shadow` 一层，非模糊），其余等大，标签为岛上浮签。
- 颜色 ＝ 库（头顶 14×3px 色 tick）／生效态／单色；PDF 用整石填充库色，一眼区分原件。

**边与标签策略：** 岛内双链直线（短、直、细，最不像草）；跨岛桥画成「索道」（翡翠 1.8px 直线横跨海沟）；语义边默认关闭。标签为节点下方浮签，缩小即按密度隐藏非 hub／非命中。

**检索态 choreography：** 问题浮标沉入海沟中央深渊 → 三环声呐圈＋索道辐条射向命中 → 命中卵石上浮（描边＋角标）→ 其余下沉 25% 透明度。转场语义是“下潜／上浮”而非“变色”，与领海方案体验完全不同。

**性能：** 岛台是天然视口裁剪单元：库过滤＝整岛 `display:none`（边同步裁剪）；首屏静态岛＋卵石；边直线（无二次贝塞尔）重绘最便宜。

## 方案 C · 星环轨道 Orbital Rings（`graph-redesign-c-orbit.html`）

**设计语言一句话：** 半径即边界 —— 三个库是三条同心轨道，节点是卫星，检索是恒星点亮辐条；库分界问题被几何本身解决。

**布局拓扑：径向同心环。** 技术笔记 130 环 · 论文阅读 235 环 · 会议记录 340 环（椭圆压扁 0.82 防宽屏拉扯），节点按度数均匀上环（hub 仍大一号），页节点内收 22px 做伴星。生产实现：布局阶段按库分配半径＋角度（确定性 golden-angle），力导向仅做环内微调＋防重叠，可彻底关掉跨库引力。

**库分界手法：轨道环。** 每库一条库色虚线轨道＋环顶 `◉ 库名` 铭牌；开关「轨道环」即开关边界。环与环之间天然 100px 真空带；跨环关系只能是“弦”（直线横贯），同环关系走“弧”（沿环二次贝塞尔），形态即语义。

**节点视觉编码：**

- 形状 ＝ 类型：统一卫星药丸＋圆形字形徽（PDF 方角药丸、缓存菱形徽旋转 45°、页虚线小药丸）。
- 大小 ＝ 重要性：hub 大徽＋粗字；其余等大。
- 颜色 ＝ 库（徽底色）／生效态／单色；字形徽底色即库色，远距离可读性三套中最高（色块最大）。

**边与标签策略：** 同环弧（细、顺环、不 crossing）· 跨环弦（翡翠高亮）· 归属短辐条 · 语义弦虚线默认关。标签在药丸内（非常态外挂），密度开关隐藏非 hub／非命中药丸文字、只留色徽 —— 缩放 OCI 友好。

**检索态 choreography：** 中央“检索恒星”点亮 → 三环声呐圈 → 辐条（恒星→命中直线）→ 命中卫星描边＋角标 → 非命中沉入暗面。清除即恒星熄灭。这是三套中检索隐喻最强的一套（问题＝太阳，答案＝被照亮的行星）。

**性能：** 环布局是 O(n) 确定性布局，无需仿真即可首屏 1s 内可交互；边多为直线弦，重绘便宜；环可整体裁剪（库过滤＝隐藏整环＋环上节点）。

## 方案 D · 汐读 Reading Tide（`graph-redesign-d-tide.html`）

**设计语言一句话：** 正文是潮汐、底图是海 —— 读字为主、瞥图为辅；图谱从主角退成右下角的导航缩略图，检索答案直接是可读的文章流。

**拓扑或组织形式：阅读流＋底图导航。** 中央阅读流（常态按库分组 sticky 节头，检索态按置信度扁平重排）＋ 右列底图导航（三块淡海域＋圆点＋强边，点圆点平滑滚到正文卡）＋ 左列图层。生产实现：复用现有检索排序（`search_knowledge` TopK 即流排序），底图复用 A 方案海域＋简化点边（只画强边），正文卡分页渲染（50/页＋虚拟滚动）。

**库分界手法（本命题重点）：双轨分界。** 正文轨：卡片左 4px 库色色脊＋ sticky 节头（库名＋篇数＋生效统计）；底图轨：三块淡海域＋库名铭牌。关闭「库分界」即两轨同步退潮（与现状 `lyBounds` 同语义，色脊回灰、海域隐藏）。

**内容呈现策略：** 每卡＝标题（可点开 Inspector）＋ 路径 mono ＋ 两行摘要（检索词 `<mark>` 高亮）＋ 标签 chips ＋ 元信息（块数／双链数／管线／更新）＋［底图定位／详情］。非命中折叠成一行（标题＋半句摘要），保证“搜到了哪几篇、每篇讲什么”一眼可读。

**检索态 choreography（常态 → 检索 4 拍）：** ① 顶部横幅“搜到 N 篇 · 按置信度重排” ② 正文流扁平重排＋ `◈ 置信度 · #排名` 角标＋非命中折叠 ③ 底图升起问题恒星＋辐条（只活在底图，正文不管） ④ 首卡自动滚入视口。清除（✕）即退潮回分组流。`prefers-reduced-motion` 下平滑滚动关闭。

**性能：** 首屏即正文流（零仿真）；600 篇走紧凑排版档（去阴影＋单行摘要，由「紧凑排版」开关／自动触发）；底图 SVG 只画圆点＋强边（语义边默认关）、点数封顶。

## 方案 E · 案牍 Dossier（`graph-redesign-e-dossier.html`）

**设计语言一句话：** 左边是卷宗架、右边是展开的卷 —— 清单管找、详情管读，关系图只在详情里露一小角（点缀）。

**拓扑或组织形式：混合视图（清单＋详情＋一跳星图）。** 左清单（分组／排序／过滤的内容清单：节头＋行，行内标题＋一行摘要＋标签＋分数条）＋ 中详情（即 Inspector 本体：摘要 → 管线 → 双链 → 语义近邻 → 命中片段 → 打开源文件）＋ 右轨图层。关系收敛为详情内一跳星图（中央本文＋ ≤7 邻居，实线双链／短虚线归属／点线语义，点邻居即跳转）。生产实现：清单即现有检索排序＋库分组；详情即现有 Inspector 数据流原样搬运；星图是 ego 一跳子图（现有边数据，不跑全图仿真）。

**库分界手法：节头色块＋星图邻居颜色。** 清单按库节头分组（色块＋篇数＋生效数，`库分组节头` 开关即边界开关）；详情头库 chip；星图邻居按库着色（图例可查）。关闭分组即扁平清单（检索态默认扁平）。

**内容呈现策略：** 清单行＝状态圆点＋标题＋一行摘要＋标签＋元信息（库／类型／块／更新），命中行加 `◈ 置信度`＋分数条；详情＝全文阅读位（大标题＋摘要段＋标签＋命中片段 `<mark>`），保证检索态“左单重排、右卷开读”。

**检索态 choreography：** ① 左顶横幅“搜到 N 篇 · 已按置信度重排” ② 清单扁平重排＋分数条＋非命中压暗 ③ 详情自动切到 #1 命中（标题＋片段高亮） ④ 星图保持点缀（不抢戏）。清除即回分组清单。清单内过滤框支持标题／标签／摘要二次过滤；排序支持相关度／更新／块数。

**性能：** 无全库大图是最大性能红利：清单行 DOM 分页（首屏 50 行＋滚动追加），星图 ≤8 节点 SVG，600 节点下比重跑全图仿真便宜一个数量级；紧凑密度档（`＋/－` 缩放切换）隐藏一行摘要。

## 方案 F · 墟集 Bazaar（`graph-redesign-f-bazaar.html`）

**设计语言一句话：** 一库一条大街、一篇一张摊卡 —— 按库分街的卡片墙，逛的是街、读的是卡、点卡下钻看关系。

**拓扑或组织形式：聚落卡片墙＋下钻。** 三条库大街（列：列头色带＋篇数＋生效统计）＋ 列内卡片（标题＋两行摘要＋标签＋块／链／管线＋下沿迷你关系 5 点封顶，点颜色＝邻居的库）＋ 点卡下钻抽屉（即 Inspector：摘要／标签／管线／双链／语义／片段／打开源文件）。附带时间线／目录树语义的落点：列内排序支持更新时间（即时间线序）与块数，关闭「库大街」即合并为混合大街（目录树扁平态）。生产实现：墙即检索排序＋库分组渲染；迷你关系取一跳邻居前 5（现有边数据）；下钻即 Inspector 数据流；卡片分页＋列内虚拟滚动。

**库分界手法：大街列。** 列本身即边界（顶色带＋整列底色＋列头统计），比 A 的海域更硬、比 B 的海沟更暖；卡片下沿圆点颜色是第二层分界（邻居来自哪条街）。关闭「库大街」即并街（与 `lyBounds` 同语义）。

**内容呈现策略：** 卡＝标题（检索词高亮）＋两行摘要＋标签＋元信息＋迷你关系 strip（`关系 — ○○○ 下钻 ▸`，无关系则诚实写“暂无（开边即有）”）；检索态命中卡描边＋ `◈ 置信度 · #排名` 角标＋列内浮顶，非命中压暗 30%，另有「仅看命中」过滤器。

**检索态 choreography：** ① 顶部横幅“搜到 N 篇 · 各列浮顶” ② 命中卡列内浮顶＋角标＋摘要高亮 ③ 非命中压暗（或被「仅看命中」滤掉） ④ 点卡下钻读全文（摘要＋片段＋关系全在抽屉）。清除即回常态逛街序。

**性能：** 卡片墙天然分页单元：列＝视口裁剪单元（库过滤＝整列隐藏）；迷你关系每卡 ≤5 点（纯 HTML 圆点，无 SVG 边，最便宜）；600 卡走小密度档（隐藏两行摘要，只留标题＋标签）。

## 推荐排序（六套，回应“纯节点不够”）

1. **F · 墟集（内容型首选落地）：** 三套内容型中分界最硬（列本身即边界）、检索态“搜到哪几篇、每篇讲什么”最直观（卡上有字、有统计、有迷你关系），且工程上全是现有数据流（排序＋分组＋Inspector 下钻），无全图仿真负担。相对 A 的位置：与 A 并列首选 —— 常态逛街（F）＋ 需要看关系时切领海（A），或直接以 F 为默认、A 为“关系视图”。建议下一版默认先上 F。
2. **A · 领海群岛（关系型首选保留）：** 仍是纯节点案里改动最小、观感提升最大的；但单看检索可读性已输给 D/E/F。相对位置：从原来的“唯一默认”退为“关系视图默认” —— 需要看跨库桥、全库拓扑时切 A，日常读内容留在 F/D。
3. **E · 案牍（次选／效率用户）：** 清单＋详情是信息密度与操作效率最高的组合（排序／过滤／分组一次齐），对 WEMM 失败排查、待办逐条过这类场景最顺手；但三栏布局在小窗口下拥挤，且完全抛弃了全库一览。相对 C 的位置：挤掉 C 的“第二视图”席位 —— 第二视图应在 E（效率）与 C（仪式感）之间二选一，效率优先选 E。
4. **D · 汐读（次选／阅读用户）：** 阅读体验最完整（摘要流＋高亮＋折叠），底图导航的“读正文、瞥底图”心智最轻；但长流在 600 篇下滚不动，必须配分页＋紧凑档。相对 B 的位置：D 与 B 都是“把分界做轻”的路子，D 用内容量换理解度，B 用密度换性能 —— 内容优先则 D 在 B 之前。
5. **C · 星环轨道（备选／检索仪式感）：** 检索隐喻仍是最强的，但“半径即边界”在内容型方案面前显得为几何而几何；建议降级为彩蛋视图（检索恒星时刻）而非第二视图。
6. **B · 深渊群岛（备选／高密度＋性能模式）：** 信息密度与显存占用仍最优，多库（5＋）扩展性最好；但美学最冷、且内容可读性为零，适合作为“极简／性能模式”而非日常视图。

## 工程改造成本与风险

| 方案 | 成本 | 改动面 | 风险点 |
|---|---|---|---|
| A 领海 | **小**（约 1–2 天） | `buildGraphDom` 加海域 path 组（由库凸包／锚点矩形生成圆角多边形）＋ `renderBounds` 改画填充＋ `paint` 加桥高亮类；CSS 新增海域＋药丸微调；其余（仿真、检索、Inspector、图层）不动 | 海域多边形过大遮挡边 → 用 `z-index`/SVG 层序把海域置底＋`pointer-events:none`；多库（6＋）配色需扩展 `LIB_COLORS`；填充透明度在浅色下需按 token 表调高否则看不见 |
| B 深渊 | **中**（约 3–5 天） | 布局：锚点→岛台中心＋跨库斥力权重；渲染：岛台 div＋海沟线＋卵石节点模板重写；边改直线；检索辐条起点改海沟中央 | 固定岛位在小窗口下拥挤 → 需岛台横向滚动或自适应缩放（`fitView` 按岛台包络）；卵石字形徽需为无字标题兜底（取首字／类型字母）；与现有玻璃卡片视觉断裂，需设计评审确认 |
| C 星环 | **中**（约 3–5 天） | 布局：新增环分配器（库→半径，节点→角度，页→伴星内收）＋力导向降级为环内微调；渲染：轨道 ellipse＋环铭牌＋卫星药丸模板；边分弧／弦两类路径函数 | 节点数不均时外环稀疏／内环拥挤 → 需按库节点数动态调半径（`r = base + k·sqrt(n)`）；环数＞4 时半径爆炸 → 需封顶＋外环分页／聚合；角度分配与增量索引（新节点上环）需确定性规则否则每次跳变 |
| D 汐读 | **小～中**（约 2–3 天） | 新增阅读流视图（分组节头＋内容卡＋横幅＋折叠）＋底图缩略 SVG（复用 A 海域＋简化点边）＋卡分页／虚拟滚动；检索排序、Inspector、图层语义全部复用 | 长流性能 → 必须分页（50/页）＋紧凑档去阴影，否则 600 篇 DOM 爆炸；底图与正文的选中同步（点圆点滚到卡）需防抖；sticky 节头在 WebView2 缩放下的层叠需实测 |
| E 案牍 | **中**（约 3–4 天） | 新增清单（分组／排序／过滤＋分数条）＋详情（Inspector 搬运＋命中片段）＋一跳星图 SVG（ego 子图，无全图仿真）；图层开关映射到星图边种 | 三栏小窗口拥挤 → 需断点折叠右轨（≤1150px 隐藏）；清单 600 行需分页追加；星图邻居缺标题时兜底（首字／类型字母）；“无大图”需向用户解释（力学 `i` 必须写清） |
| F 墟集 | **小～中**（约 2–3 天） | 新增大街列（库分组＋列头统计）＋卡片墙（卡＋strip＋角标＋仅看命中）＋下钻抽屉（Inspector 搬运）；排序（相关度／更新／块数）＋密度档 | 列数＞4 时横向拥挤 → 需横向滚动或并街；strip 每卡 5 点封顶规则要写死，否则 600 卡 × 全邻居＝DOM 爆炸；下钻与 Inspector 去重（共用一套数据函数，勿各写一份） |

通用风险（常量）：语义边仍走 `semantic_edges()` 懒加载（阈值滑杆、防抖＋加载中 toast）；600 节点下六套都要保留 `labels-min`＋`perf` 去阴影＋`prefers-reduced-motion` 全关；`backdrop-filter` 继续禁用（本 demo 已验证实底浮层观感成立）。
